# สถาปัตยกรรมระบบ

เอกสารนี้อธิบายว่าระบบประกอบด้วยส่วนใดบ้าง แต่ละส่วนทำหน้าที่อะไร และข้อมูลไหลอย่างไร
สำหรับผู้ดูแลระบบและฝ่ายไอทีของโรงพยาบาลที่ต้องประเมินก่อนตัดสินใจ

---

## ส่วนประกอบ

ระบบแยกเป็น 3 ส่วนที่รันคู่กัน แต่ติดตั้งเป็นชุดเดียวและผู้ใช้เห็นเป็นระบบเดียว

| ส่วน | เทคโนโลยี | หน้าที่ |
|---|---|---|
| **เว็บ** | Next.js (TypeScript) | หน้าจอทั้งหมด ผู้ใช้และสิทธิ์ ตรรกะทางธุรกิจ |
| **บริการ AI** | Python (FastAPI) | ค้นคลังความรู้ อ่านเอกสารสแกน เรียกโมเดลภาษา จัดกลุ่ม DRG |
| **ตัวเชื่อมข้อมูล** | Python (FastAPI) | ดึงข้อมูลจาก HosXP นำเข้าไฟล์ สปสช./ประกันสังคม/43 แฟ้ม งานตามตาราง |

### ทำไมต้องแยกสามส่วน

ไม่ได้แยกเพื่อความซับซ้อน แต่แยกเพราะแต่ละส่วนมีข้อจำกัดต่างกันจริง

- **บริการ AI** ต้องเป็น Python เพราะเครื่องมืออ่านเอกสารภาษาไทย ตัวจัดกลุ่ม DRG
  และไลบรารีอ่านไฟล์รูปแบบเฉพาะของ สปสช. มีเฉพาะบน Python
- **ตัวเชื่อมข้อมูล** ต้องแยกเพราะงานดึงข้อมูลย้อนหลังรันต่อเนื่องเป็นชั่วโมง
  ถ้ารวมกับเว็บ หน้าจอจะค้างระหว่างที่งานทำงานอยู่
- **เว็บ** แยกออกมาเพื่อให้ผู้ใช้ยังใช้งานได้ตามปกติแม้อีกสองส่วนกำลังทำงานหนัก

---

## บริการเสริมที่ต้องรันคู่กัน

| บริการ | หน้าที่ | จำเป็นเมื่อ |
|---|---|---|
| **PostgreSQL** | ฐานข้อมูลของระบบ | เสมอ |
| **Qdrant** | เก็บคลังความรู้สำหรับค้นหา | ใช้โมดูลที่ต้อง AI |
| **Ollama** | รันโมเดลภาษาบนเครื่องของโรงพยาบาล | ใช้โมดูลที่ต้อง AI |

---

## ข้อมูลไหลอย่างไร

### การดึงข้อมูลจาก HosXP

```
HosXP (MySQL)  ──อ่านอย่างเดียว──▶  ตัวเชื่อมข้อมูล  ──▶  PostgreSQL ของระบบ
                                                              │
                                                              ▼
                                                         หน้าจอรายงาน
```

ระบบ**ไม่อ่านจาก HosXP โดยตรงทุกครั้งที่เปิดรายงาน** แต่ดึงมาเก็บไว้ก่อนเป็นรอบ
เพื่อไม่ให้กระทบการทำงานของ HosXP ในเวลาทำการ

ข้อมูลที่ต้องสดจริง ๆ เท่านั้น (เช่น จำนวนผู้ป่วยในที่ยังนอนอยู่ สถานะคิว OPD)
ที่ยิงไปถาม HosXP สด ๆ ด้วยคำสั่งเบา ๆ และถ้าเชื่อมต่อไม่ได้ หน้าจอจะแสดงส่วนอื่นตามปกติ

### การวิเคราะห์ด้วย AI

```
เคสผู้ป่วย  ──▶  บริการ AI  ──▶  ค้นเกณฑ์ที่เกี่ยวข้องจากคลังความรู้ (Qdrant)
                     │
                     ├──▶  ส่งให้โมเดลภาษาบนเครื่อง (Ollama) วิเคราะห์
                     │
                     └──▶  ผลลัพธ์ + เอกสารอ้างอิง  ──▶  เก็บใน PostgreSQL
```

ผลการวิเคราะห์เป็น **ข้อเสนอแนะให้คนตรวจ** ไม่ใช่การตัดสินใจแทน
และแสดงเอกสารอ้างอิงประกอบเสมอ เพื่อให้ผู้ใช้ตรวจสอบที่มาได้

---

## ความเป็นส่วนตัวของข้อมูล

**ข้อมูลผู้ป่วยไม่ออกจากเครือข่ายของโรงพยาบาลในทุกขั้นตอน**

- โมเดลภาษารันบนเครื่องของโรงพยาบาลเอง ไม่เรียก API ของผู้ให้บริการ AI ภายนอก
- คลังความรู้เก็บบนเครื่องเดียวกัน
- การเชื่อมต่อออกภายนอกมีเฉพาะ 3 กรณี ซึ่งไม่มีข้อมูลผู้ป่วยรายบุคคล
  - ดึงตัวชี้วัดสาธารณะจาก opendata ของกระทรวง
  - ล็อกอินด้วย Provider ID ของกระทรวง (เฉพาะการยืนยันตัวตนเจ้าหน้าที่)
  - ดึงผลตรวจสอบจากเว็บ สปสช. ด้วยบัญชีของโรงพยาบาลเอง

---

## ระบบสิทธิ์

สิทธิ์แบ่งตามโมดูล และบังคับใช้ 3 ชั้นที่แยกจากกัน

```
ผู้ใช้ร้องขอหน้า
      │
      ▼
ชั้นที่ 1  ก่อนเข้าถึงหน้า  ──▶  ตรวจจากข้อมูลที่ติดมากับการล็อกอิน (เร็ว)
      │
      ▼
ชั้นที่ 2  ก่อนแสดงหน้า    ──▶  ตรวจจากฐานข้อมูลโดยตรง (ชี้ขาด)
      │
      ▼
ชั้นที่ 3  ที่ API แต่ละตัว ──▶  ตรวจซ้ำก่อนคืนข้อมูล
```

ทำสามชั้นเพราะแต่ละชั้นมีจุดอ่อนคนละแบบ — ชั้นแรกเร็วแต่ข้อมูลอาจไม่ทันสมัยที่สุด
ชั้นที่สองแม่นยำแต่ทำงานหลังจากโหลดหน้าแล้ว ส่วนชั้นที่สามกันกรณีที่มีผู้เรียก API โดยตรง

โมดูลที่มีข้อมูลรายบุคคล (การเงิน รายงานตรวจสุขภาพ ส่งยาที่บ้าน) ถูกทำเครื่องหมายแยก
และต้องได้รับอนุมัติจากผู้ดูแลเสมอ ไม่ได้มาพร้อมกลุ่มสิทธิ์โดยอัตโนมัติ

---

## การแยกเป็นโมดูล

ทุกโมดูลประกาศไว้ที่เดียวในระบบ พร้อมข้อมูลว่า

- อยู่ที่ URL ไหน และ API ใดเป็นของโมดูลนั้น
- ต้องติดตั้งคู่กับโมดูลใด
- ต้องมีบริการหรือบัญชีภายนอกอะไร
- เก็บข้อมูลไว้ที่ตารางใด (ใช้ตอบคำถามผู้ตรวจสอบเรื่อง PDPA)

การประกาศไว้ที่เดียวทำให้เมนู การกันสิทธิ์ และเอกสารประกอบตรงกันเสมอ
ไม่เกิดกรณีที่เพิ่มหน้าใหม่แล้วลืมกันสิทธิ์

---

## การอัปเดต

ทุกหน่วยบริการใช้ระบบเวอร์ชันเดียวกัน สิ่งที่ต่างกันคือ

- ข้อมูลหน่วยบริการ (รหัส ชื่อ จังหวัด หน่วยลูกใน CUP)
- โมดูลที่เปิดใช้
- การตั้งค่าเชื่อมต่อ HosXP

การออกแบบเช่นนี้ทำให้แก้ปัญหาที่พบในโรงพยาบาลหนึ่งแล้วทุกที่ได้ประโยชน์ร่วมกัน
ไม่แตกเป็นระบบคนละตัวที่ดูแลแยกกันไม่ไหว
